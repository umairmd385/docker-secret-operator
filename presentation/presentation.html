The Solution

What is DSO?

DSO is a native Docker CLI plugin that connects your cloud secret vaults directly to your running containers at runtime.

  • No .env files — ever
  • Nothing written to disk
  • Works with your existing Docker Compose
  • No Kubernetes required
  • Multi-cloud: AWS, Azure, Vault, Huawei
  • Written in Go — ~20MB RAM, <1% CPU
# 1. Install
$ curl -fsSL .../install.sh | sudo bash

# 2. Configure dso.yaml
provider: aws
secrets:
  - name: prod/db-password
    inject: env

# 3. Run
$ docker dso up -d

✓ Secrets injected. Containers running.
Core Workflow

docker dso up -d — step by step

1
Read Configuration
Parses docker-compose.yml + dso.yaml. Identifies which secrets map to which containers.
2
Authenticate (No Manual Passwords)
Connects to cloud vault using IAM instance roles, service principals, or Vault tokens. Zero manual credential input.
3
Inject Secrets — In Memory Only
Secrets are fetched and held in RAM. Delivered to containers via Docker Unix Socket — never written to disk.
4
Boot Stack + Start Watcher
Containers start with enriched environment. Background Watcher Engine begins monitoring for secret drift.

Intelligent Rotation

The Strategy Engine

DSO doesn't blindly restart containers. It thinks first.

CONTAINER SCORE (starts at 100)
Fixed port binding
-50
Explicit container name
-20
restart_always policy
-20
No health check
-10
Stateful workload
-20
Score ≥ 70 → 🔄 Rolling (Blue/Green)

Clone container → inject new secrets → health-check gateway → cut traffic → remove old container. Zero downtime.

Score < 70 → 🔁 Graceful Restart

Used for stateful apps (databases, fixed-port services). Safe shutdown → secret update → restart. No data corruption.

Security

Security-First Design

🔒 Secrets Never Touch Disk

All secret values are held in RAM only. Injected via Unix socket into container environment. Purged on agent shutdown. Zero persistence. By design.

🔑 Zero Manual Credentials

Uses cloud-native machine identity: AWS IAM Instance Profiles, Azure Managed Identity, Vault AppRole. No passwords stored anywhere.

Watch Modes
📊 Polling Mode

Checks vault on a configurable interval (e.g., every 30s). Simple and reliable.

⚡ Event Mode

Receives webhook calls from your vault or CI pipeline for instant rotation.

🔀 Hybrid Mode

Polling as safety net + events for instant response. Best of both worlds.

Configuration

dso.yaml Full Schema

provider: aws
region: us-east-1

agent:
  cache: true
  refresh_interval: 5m
  auto_sync: true
  watch:
    mode: hybrid # polling|event|hybrid
    polling_interval: 30s
  rotation:
    strategy: rolling
    health_check_timeout: 30s
    max_parallel: 2
secrets:
  - name: prod/db-credentials
    inject: env # env|file|socket
    rotation: true
    reload_strategy:
      type: signal # signal|restart|none
    mappings:
      DB_PASS: DB_PASSWORD
      DB_USER: DATABASE_USER

  - name: prod/tls-cert
    inject: file
    path: /run/secrets/tls.crt
Developer Experience

CLI Reference

All commands are first-class Docker subcommands — no bash wrappers

CommandDescription
docker dso up -d Start Compose stack with secrets injected. Detached mode.
docker dso down Stop stack and securely purge all in-memory secrets
docker dso compose <cmd> Run any Docker Compose subcommand with DSO secret injection
docker dso fetch <name> Fetch and display a specific secret value from the vault
docker dso watch Start continuous background secret watcher
🔌 Installed to ~/.docker/cli-plugins/docker-dso
