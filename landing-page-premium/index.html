Docker Secret Operator

Sync and manage secrets from external providers directly into Docker containers — without manual updates or restarts.

Get Started View on GitHub

Managing secrets in Docker is difficult

Most Docker environments handle secrets manually, which creates real operational and security problems.

  • Secrets are hardcoded or manually injected via .env files
  • Updating secrets requires pulling containers down and restarting
  • No native integration with cloud secret managers (AWS, Azure, Vault)
  • Rotation is manual and error-prone — easy to miss a running container

DSO connects Docker to your secret provider

DSO runs as a local agent alongside Docker. It connects to your external secret store and keeps containers in sync.

Fetches secrets from providers like AWS Secrets Manager and Azure Key Vault
Injects them into containers as environment variables or mounted files
Keeps containers updated when values change — no manual updates, no restarts

How it works

Four steps from secret store to running container.

1

Store secrets

Add your secrets to AWS Secrets Manager, Azure Key Vault, or another supported provider.

2

DSO fetches

The DSO agent polls the provider and retrieves the secret values over a secure connection.

3

DSO injects

Secrets are pushed into running containers as environment variables or file mounts.

4

Auto-updated

When the upstream value changes, containers receive the new value automatically.

Example usage

Define your provider and secret mapping in dso.yaml, then use DSO to bring your stack up.

dso.yaml

dso.yaml 
provider: aws

config:
  region: us-east-1

secrets:
  - name: my-app-secret
    inject: env
    mappings:
      DB_PASSWORD: DATABASE_PASS
      DB_USER: DATABASE_USER

docker-compose.yaml

docker-compose.yaml 
services:
  app:
    image: my-app:latest
    environment:
      - DB_PASSWORD_FILE=/run/secrets/DB_PASSWORD
      - DB_USER_FILE=/run/secrets/DB_USER

DSO reads dso.yaml, pulls the values from AWS Secrets Manager, and injects them into the running container. When the secret is rotated in AWS, DSO detects the change and updates the container automatically.

Features

Everything you need to manage secrets in a Docker environment.

Secret Sync

Automatically fetch secrets from AWS Secrets Manager, Azure Key Vault, HashiCorp Vault, Huawei CSMS, and more.

Secret Rotation

DSO polls the provider on a configurable interval. When values change, containers receive the updated secret automatically.

Multi-Provider Support

Works with AWS, Azure, Vault, Huawei, and local file or environment sources. Switch providers by changing one line in dso.yaml.

No Restarts Required

Updated secrets are pushed into running containers without stopping or restarting them.

Works with Docker Compose

Use dso compose up — a transparent wrapper around docker compose that handles secret injection automatically.

No Kubernetes Required

DSO runs as a lightweight systemd service. No cluster, no sidecars, no Helm charts needed.

Architecture

DSO runs as a background agent between your secret provider and your Docker containers.

↓
Application Container

Reads secrets at runtime

1

DSO runs as a service alongside Docker

Installed via a single script. Runs as a systemd unit — no cluster or orchestrator required.

2

Pulls secrets from external providers

Uses provider-specific plugins (Go binaries) to connect to AWS, Azure, Vault, and others. Credentials are read from the host environment.

3

Stores locally (file or volume)

Secrets are written to a local path or mounted volume. They never appear in compose files or environment dumps.

4

Updates propagate automatically

When a secret is rotated upstream, DSO detects it within the polling interval and pushes the new value into the running container.

Getting started

DSO is installed as a systemd service. The installer handles binaries, plugins, and systemd setup.

1

Install DSO

curl -fsSL https://raw.githubusercontent.com/umairmd385/docker-secret-operator/main/install.sh | sudo bash
2

Configure your provider credentials

Add your cloud provider credentials to the host environment (e.g., AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY for AWS).

3

Create /etc/dso/dso.yaml

provider: aws

config:
  region: us-east-1

secrets:
  - name: my-app-secret
    inject: env
    mappings:
      DB_PASSWORD: DATABASE_PASS
4

Start the agent and deploy

sudo systemctl start dso-agent
dso compose up -d
