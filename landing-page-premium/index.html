What is Docker Secret Operator?

DSO is a native Docker plugin that bridges the gap between your cloud secret managers and your running containers. No Kubernetes. No sidecars. No jargon.

✓

Multi-Cloud: Fetches from AWS, Azure, Vault, and more.

✓

Zero-Restart: Updates secrets in-place without killing your service.

Secrets never touch disk.

All secret values are held in memory only, injected via Unix socket. Zero persistence by design.

Secrets update in-place. Zero downtime rotation.

Unified

Get started in seconds

Three steps to secure secret injection.

1

Install Plugin

Terminal 
curl -fsSL https://raw.githubusercontent.com/umairmd385/docker-secret-operator/main/install.sh | sudo bash

Installs ~/.docker/cli-plugins/docker-dso — a first-class Docker subcommand.

2

Configure

dso.yaml 
provider: aws
config:
  region: us-east-1
secrets:
  - name: prod/db-credentials
    inject: env
    rotation: true
    mappings:
      DB_PASS: DB_PASSWORD

Place at /etc/dso/dso.yaml or pass via --config.

3

Run

Terminal 
$ docker dso up -d
# Verify injection:
$ docker dso fetch prod/db-credentials
✔ Secrets injected. Stack running. Watcher active.

How it works

Four steps from secret store to running container.

1

Store secrets

Add your secrets to AWS Secrets Manager, Azure Key Vault, or another supported provider.

2

DSO fetches

The DSO agent polls the provider and retrieves secret values over a secure connection.

3

DSO injects

Secrets are pushed into running containers as env vars or via /run/secrets/ file mounts.

4

Auto-updated

When the upstream value changes, containers receive the new value automatically. No restart needed.

Example usage

Two files. That's all you need.

/etc/dso/dso.yaml 
# Provider configuration
provider: aws

config:
  region: us-east-1

agent:
  watch:
    polling_interval: 2m

secrets:
  - name: my-app-secret
    inject: env
    mappings:
      DB_PASSWORD: DATABASE_PASS
      DB_USER:     DATABASE_USER
docker-compose.yaml 
services:
  app:
    image: my-app:latest
    environment:
      - DB_PASSWORD_FILE=/run/secrets/DB_PASSWORD
      - DB_USER_FILE=/run/secrets/DB_USER

  db:
    image: postgres:16
    environment:
      - POSTGRES_PASSWORD_FILE=/run/secrets/DB_PASSWORD
$ docker dso compose up -d # DSO reads dso.yaml → fetches from AWS → injects into containers → starts stack

Security Model

Built for trust, not just compliance

Every design decision in DSO is a security decision. Here's exactly what happens with your secrets.

Memory-Only Store

Secrets are held in the agent's in-process RAM. Never written to the filesystem. Purged on shutdown.

Unix Socket Transport

CLI↔Agent communication happens over a local Unix socket. No network exposure, no TLS to manage.

IAM Role Auth — Zero Credentials on Host

DSO uses EC2 Instance Profiles, Managed Identity, and Vault AppRole. No static keys stored on the machine.

Structured Audit Logs

Every fetch, rotation, and strategy decision is logged in JSON. Forward to Splunk, Datadog, or CloudWatch.
